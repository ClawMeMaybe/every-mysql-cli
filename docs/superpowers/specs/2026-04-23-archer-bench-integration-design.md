# Archer-Bench Integration Design Spec

**Date:** 2026-04-23
**Approach:** Conversion tool + Go benchmark test suite (Approach A)

## Overview

Integrate the Archer text-to-SQL benchmark dataset (https://sig4kg.github.io/archer-bench/) as a local MySQL-based benchmark for the every-mysql-cli generator. The Archer dataset contains 10 SQLite databases across diverse domains (world, concert_singer, bike_1, customers_and_products_contacts, driving_school, formula_1, hospital_1, riding_club, soccer_1, wine_1) with varied schema complexity — from 3-table simple schemas to 15-table complex schemas with composite PKs and FK chains.

Since the generator is MySQL-only, we convert the SQLite databases to MySQL, spin up a local MySQL instance via Docker Compose, and validate both CRUD correctness and schema robustness of each generated CLI.

## Architecture & Components

Three new components, each with one clear purpose:

### 1. SQLite-to-MySQL Converter (`internal/bench/convert.go`)

Reads each `.sqlite` file and produces a MySQL `.sql` file containing `CREATE TABLE` + `INSERT` statements.

**API:**

```go
func ConvertAll(zipPath string, outputDir string) error
func ConvertSingle(sqlitePath string, dbName string, outputPath string) error
```

**Type mapping (SQLite → MySQL):**

| SQLite type | MySQL type |
|---|---|
| INTEGER, INT | INT |
| TEXT | TEXT |
| REAL, FLOAT | DOUBLE |
| NUMERIC | DECIMAL(10,2) |
| VARCHAR(N) | VARCHAR(N) |
| CHAR(N) | CHAR(N) |
| BOOLEAN | BOOLEAN |
| DATETIME, DATE | DATETIME, DATE |
| BLOB | BLOB |

**ConvertSingle flow:**

1. Open SQLite with `go-sqlite3`
2. For each user table (from `sqlite_master WHERE type='table' AND name NOT LIKE 'sqlite_%'`):
   - Parse columns via `PRAGMA table_info` — name, mapped type, nullable, default, autoincrement
   - Parse FKs via `PRAGMA foreign_key_list` — column, referenced table, referenced column, on_update/on_delete
   - Detect primary keys via `pk` column flag in `PRAGMA table_info`, handle composite PKs
   - Build MySQL `CREATE TABLE` statement with mapped types, constraints
3. For each table, read all rows and generate `INSERT` statements with proper value escaping
4. Preamble: `CREATE DATABASE IF NOT EXISTS <name>; USE <name>;`
5. Write combined output to `<name>.sql`

**ConvertAll flow:**

1. Open the archer-bench `database.zip`
2. Extract each `.sqlite` file to a temp directory
3. Call `ConvertSingle` on each
4. Write resulting `.sql` files to `outputDir`
5. Clean up temp files

**Edge cases handled:**
- `sqlite_sequence` tables are skipped (auto-generated by SQLite for AUTOINCREMENT)
- `.ipynb_checkpoints` directories are ignored
- Composite primary keys produce `PRIMARY KEY (col1, col2)` syntax
- Tables with no rows still get `CREATE TABLE` statements

### 2. Docker Compose MySQL (`docker-compose.yaml`)

Single MySQL 8.0 service at the project root:

```yaml
services:
  bench-mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: benchroot
      MYSQL_ROOT_HOST: "%"
    ports:
      - "13306:3306"
    volumes:
      - ./testdata/archer-bench/sql:/docker-entrypoint-initdb.d
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-pbenchroot"]
      interval: 5s
      timeout: 3s
      retries: 10
```

**Key decisions:**
- Port 13306 mapped to container 3306 — avoids conflicts with existing MySQL on host
- `docker-entrypoint-initdb.d` — MySQL's official image auto-executes `.sql` files on first startup, so all 10 databases load automatically
- Healthcheck — benchmark test waits for this before running generator
- Root password `benchroot` — only for benchmarking, never production

### 3. Benchmark Test Suite (`internal/bench/benchmark_test.go`)

Orchestrates the full flow: convert → start Docker → generate → validate → tear down.

### 4. Fixture Loader (`internal/bench/fixtures.go`)

Handles the archer-bench dataset:

```go
func EnsureDatabaseZip() (string, error)  // Returns path to database.zip, downloads if missing
func ExtractSQLiteFiles(zipPath string, destDir string) ([]string, error)  // Extracts .sqlite files
```

- `EnsureDatabaseZip` checks if `testdata/archer-bench/database.zip` exists locally; if not, downloads from `https://sig4kg.github.io/archer-bench/dataset/database.zip`
- `ExtractSQLiteFiles` extracts only `.sqlite` files (skipping `.db` files which are empty and `.ipynb_checkpoints`)

## Project Structure

New files:

```
internal/bench/
  convert.go          # SQLite→MySQL conversion logic
  convert_test.go     # Conversion correctness tests
  benchmark_test.go   # Main benchmark: Docker setup, generate, validate
  fixtures.go         # Fixture loading, archer-bench zip download/extraction
docker-compose.yaml   # MySQL 8 container for benchmark
testdata/
  archer-bench/
    database.zip      # Fetched by EnsureDatabaseZip() if not present locally; not committed to repo (6.5MB)
```

Converted SQL files written to `testdata/archer-bench/sql/` at runtime. Both `database.zip` and `sql/` are gitignored — they are fetched/generated on demand.

## Validation Design

### CRUD Correctness (per database, per table)

For each table in each generated CLI, run a full CRUD cycle:

| Step | Action | Validation |
|---|---|---|
| Create | `<cli> <table> create --col1 val1 --col2 val2` | Exit code 0, stdout contains inserted row |
| Read back | `<cli> <table> list --json` | JSON output contains the created row with matching values |
| Get by PK | `<cli> <table> get <pk_val> --json` | JSON output has exactly that row |
| Update | `<cli> <table> update <pk_val> --col1 newval` | Exit code 0 |
| Verify update | `<cli> <table> get <pk_val> --json` | Updated column shows newval |
| Delete | `<cli> <table> delete <pk_val> --force` | Exit code 0 |
| Verify delete | `<cli> <table> get <pk_val> --json` | Empty result or error (row gone) |

Tables without a PK skip get, update, delete — only list and create are validated.

### Robustness Checks (per database)

| Check | What it tests | Expected behavior |
|---|---|---|
| Tables with composite PKs | hospital_1 has Affiliated_With with composite PK (Physician, Department) | Generated CLI omits single-PK get/update/delete for that table, supports composite PK variants |
| Composite PK tables | e.g., Affiliated_With(Physician, Department) | get/update/delete accept two PK arguments |
| Nullable columns | Many tables have nullable fields | create works with omitted nullable flags, returns null in JSON |
| Empty result set | `<cli> <table> get 99999` | Returns empty/zero-result gracefully, no crash |
| Destructive guard | `<cli> <table> delete <pk>` without `--force` | Exit code non-zero, error message printed |
| FK helpers (outbound) | `--by-<table>` flags on list | Flag exists, filters correctly |
| FK helpers (inbound) | `--with-<table>` flags on get | Flag exists, nested data in JSON output |
| `--json` output | All commands with `--json` | Valid JSON, contains data and meta fields |

### Reporting

Test outputs a structured summary per database:

```
=== world_1 ===
  Tables: 3 (city, country, countrylanguage)
  CRUD: PASS (4/4 tables)
  Robustness: PASS (6/7 checks — no inbound FK references in this schema)
```

Any failure is a test failure with a clear error message showing which command failed and what was expected vs. actual.

## Benchmark Test Flow

1. `ConvertAll` — convert archer-bench SQLite databases to MySQL SQL fixtures
2. `docker compose up -d` — start MySQL container, fixtures auto-loaded
3. Poll healthcheck until healthy (max 60s timeout)
4. For each database:
   - Run `every-mysql-cli init --host localhost --port 13306 --user root --password benchroot --database <name> --output <tmpdir>/<name>-cli`
   - Run CRUD correctness validation on the generated CLI
   - Run robustness checks on the generated CLI
   - Collect results
5. `docker compose down -v` — tear down and remove volumes
6. Report aggregate results, fail test if any validation failed

## Dependencies Added

- `github.com/mattn/go-sqlite3` — only in `internal/bench/`, not in the generator itself
- Docker Compose — required on host machine for running benchmark tests

## Existing Infrastructure Compatibility

- Follows the pattern of `internal/generator/e2e_test.go` which already runs end-to-end tests
- Benchmark tests are tagged with `//go:build bench` to avoid running in normal test cycles
- Docker dependency is documented in README — `go test -tags bench ./internal/bench/` to run benchmarks
